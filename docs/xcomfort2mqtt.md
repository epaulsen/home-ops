# xComfort2MQTT

Runs [`epaulsen/xcomfort2mqtt:1.0.1`](https://hub.docker.com/r/epaulsen/xcomfort2mqtt/tags?name=1.0.1)
from [`epaulsen/xcomfort-dotnet`](https://github.com/epaulsen/xcomfort-dotnet).
Argo CD manages `overlays/nuc-prod/xcomfort2mqtt` through the
`home-ops-xcomfort2mqtt` Application. It connects to the existing `mqtt:1883`
broker using `mqtt-credentials` (`username` and `password`); do not copy those
credentials into another Secret.

The bridge IP is supplied as `XComfort__Host` from ConfigMap
`xcomfort2mqtt-config` (`host`). The bridge auth key is supplied as
`XComfort__AuthKey` from Secret `xcomfort2mqtt-credentials` (`auth-key`).
Neither object is generated by GitOps: provision and back them up separately.
Never commit the auth key or generated Secret YAML.

## Before merging / first sync

Merging enables automated deployment. Run these steps first with an authorized
cluster context; the PR does not execute them. Ensure no other instance is
publishing to the same MQTT topic prefix (`xcomfort2mqtt`) or using its MQTT
client ID (`xcomfort2mqtt-web`).

### Prepare storage

The new PV `xcomfort2mqtt-data-pv` binds only to PVC `xcomfort2mqtt-data`,
with `Retain` reclaim policy. Existing PVs/PVCs are not changed. Before making
storage changes, inspect bindings and confirm backups of existing data:

```bash
kubectl get pv
kubectl -n home-ops get pvc
```

On `glumserver`, create a **new, empty** data directory. If this path already
exists, stop and inspect its contents and backup rather than changing ownership
or overwriting data. The .NET image runs as UID/GID `1654`:

```bash
sudo test ! -e /home/epaulsen/containers/hass/volumes/xcomfort2mqtt-data &&
  sudo install -d -o 1654 -g 1654 -m 0750 \
    /home/epaulsen/containers/hass/volumes/xcomfort2mqtt-data
```

This directory is mounted at `/app/data`. Back up its energy totals
(`energy.json`) and retained-MQTT publication manifest (`mqtt-publications.json`)
off-host. For a consistent backup, stop this Deployment through GitOps before
copying its data. During recovery, restore the directory and UID/GID `1654`
ownership before enabling the Application. `Retain` is not a backup.

### Set bridge IP and auth key

Run in Bash with shell tracing disabled (`set +x`). The auth key is read without
echo and passed on standard input, not as a command-line argument or a literal
in shell history. Keep it in a secure password manager for recovery.

```bash
set +x
set -o pipefail
read -rp 'xComfort bridge IP address: ' XCOMFORT_HOST
if [ -z "$XCOMFORT_HOST" ]; then
  printf 'Bridge IP is required; configuration was not created.\n' >&2
else
  kubectl -n home-ops create configmap xcomfort2mqtt-config \
    --from-literal=host="$XCOMFORT_HOST" \
    --dry-run=client -o yaml | kubectl apply -f -
fi
unset XCOMFORT_HOST

read -rsp 'xComfort auth key: ' XCOMFORT_AUTHKEY
printf '\n'
if [ -z "$XCOMFORT_AUTHKEY" ]; then
  printf 'Auth key is required; Secret was not created.\n' >&2
else
  printf '%s' "$XCOMFORT_AUTHKEY" |
  kubectl -n home-ops create secret generic xcomfort2mqtt-credentials \
    --from-file=auth-key=/dev/stdin \
    --dry-run=client -o yaml | kubectl apply -f -
fi
unset XCOMFORT_AUTHKEY
```

Confirm both commands succeeded before merging. The manifests require both
objects and the existing `mqtt-credentials` Secret; missing configuration
prevents the container from starting.

## Verify after merge

Allow Argo CD to sync; do not apply workload manifests manually.

```bash
kubectl -n argocd get application home-ops-infra home-ops-xcomfort2mqtt
kubectl -n home-ops get pvc xcomfort2mqtt-data
kubectl -n home-ops rollout status deployment/xcomfort2mqtt --timeout=180s
kubectl -n home-ops logs deployment/xcomfort2mqtt --tail=100
kubectl -n home-ops port-forward service/xcomfort2mqtt 8080:8080
```

With the port-forward running, use another terminal:

```bash
curl --fail http://localhost:8080/health
curl --fail http://localhost:8080/api/devices
```

`/health` and the Kubernetes probes check the HTTP process, not bridge/MQTT
connectivity. Confirm both connections in the API/logs and verify MQTT
discovery in Home Assistant. The Service is cluster-internal; no Ingress or
external port is added.

## Configuration changes and rollback

To change the bridge IP or rotate its auth key, repeat the corresponding
configuration command above, then explicitly restart the Deployment to reload
environment variables:

```bash
kubectl -n home-ops rollout restart deployment/xcomfort2mqtt
kubectl -n home-ops rollout status deployment/xcomfort2mqtt --timeout=180s
```

Changes to `mqtt-credentials` also require a restart. Coordinate MQTT credential
rotation with the broker and its other clients.

For rollback, disable the workload through Git (set replicas to zero) before
reverting the Application registration. Automated pruning can remove its PVC
and PV objects, but `Retain` preserves the host data. Do not delete the data
directory or reuse it for another workload. Rebinding a retained volume after
PVC deletion requires an explicit recovery plan; do not clear bindings blindly.
Keep the external ConfigMap, Secret and data backup for a later redeployment.
Removing the workload does not remove its retained MQTT discovery messages.
